# TokTier 0.2.10 (draft; not released)

TokTier 0.2.10 is a Python-surface release over an unchanged native
engine. It adds a certified chunk-parallel encode for long requests on
the CPU route, a patch-only session append, a serving guide that says
which encode call fits which request shape, and the wiring of the first
two into the SGLang adapter. No served id changes on any input over any
packaged artifact; the store format, the shipped fatbin, the kernel ABI
and the three source identities (fast_cpu, native_host, rust_api) are
unchanged, because no file in their path sets moved.

Version axes moved by this release (see `docs/contracts/versioning.md`):
the package version (axis 1) moves to 0.2.10. The public API version,
registry schema version, store format version, kernel ABI version and
certification suite version do not move. The append-only `R_*` reason
namespace gains two codes (below), which is an addition the contract
allows and a consumer that switches on known codes passes through.

## Chunk-parallel encode on the CPU route (`toktier.cpe`)

A single encode runs on one core, and for an input of several hundred
thousand characters that is tens of milliseconds even on the certified
CPU engine. `toktier.cpe.chunked_encode(tokenizer, text)` cuts the
input at certified stable boundaries, runs the chunks as one batch on
the engine's worker pool, and concatenates the id rows. The result is
the serial encoding by construction: a cut is placed only where the
pre-tokenizer of the certified byte-level BPE families cannot carry a
pre-token across it, which is the synchronizing-transition rule the
session-repair witness already uses (eight class pairs over the frozen
O/S/L/N/M table, minus a line break after punctuation and an apostrophe
after letters), plus a guard that keeps every cut outside any
added-token literal of the loaded artifact. There is no seam to repair
and nothing to retry; a position where no certified cut can be found is
not cut.

What it is and is not. It is a helper over the public batch path: the
chunks go through the same plan, the same per-input guards and the same
fallback ledger as any document, so a chunk that trips a guard is
routed to the reference on its own (which localizes that cost to one
chunk instead of the whole document). It is not a new route and not a
native change: the cut search and the concatenation are Python, and the
parallelism is the native batch worker pool (`RAYON_NUM_THREADS` at
first use; at most one worker per 64 KiB of payload).

Admission and fallbacks. A tokenizer may be chunked when its family and
artifact digest have an entry in the certified repair roster -- the
eleven byte-level BPE artifacts the sync profile was certified on -- and
its loader face carries no normalizer, the empty normalizer sequence, or
NFC with every added token matched on the input text. Any other
tokenizer is encoded serially under `R_CPE_FAMILY_UNSUPPORTED` (the
refusal is named in the `cpe` block), and a document with no certified
cut is encoded serially under `R_CPE_NO_CUT`; both are new run-time
reason codes (`docs/contracts/routing.md` Section 5.2) and both are
counted in a `cpe` block of `explain()`, not in the routing ledger's
top-level `fallback_counts`, because the serial route is the same
certified backend the chunks would have used.

Normalizing families. The cut rule speaks about the text the
pre-tokenizer sees, which for an NFC family (qwen3_8b, qwen3_5_08b,
minimax_m3 on the roster) is the normalized text; a review of the
release candidate showed a cut certified on input characters alone
changing ids there (U+0958 before a slash: a letter-to-punctuation
transition as written, a mark sharing the slash's pre-token once
normalized). For such a family a candidate cut is now accepted only when
it is also a certified cut of the normalized text -- a stable split
point on both sides (a character NFC cannot change from either
neighbour, decided with the artifact's own normalizer), no added-token
literal in the anchored window, the normalizer mapping the window to
the concatenation of its halves, and the rule holding on the two
normalized characters at the cut; three stable characters around a cut
need no window at all, so prose, code and CJK text keep their cuts.
`docs/serving.md` Section 3 states the condition; `norm_rejects` counts
the candidates it declined. The shipped test judges the fix on a
generated corpus of decomposing characters, combining sequences, jamo,
kana voicing marks and literals beside marks, and a 220,000-string run
of that corpus over six roster families (100,000 on qwen3_8b) found no
id difference against the from-scratch reference, where the
release-candidate rule differed on about two percent of the qwen3_8b
strings. Two smaller contract corrections from the same review: the
quick part of the cut search is bounded by a smaller `scan_budget`, and
`min_chunk` binds the last chunk as well as the others.

The chunk table. With `k=None` the chunk count follows a staircase
(one chunk below 256 K characters, 4 up to 1 M, 16 up to 4 M, 32 above,
capped by one chunk per 64 KiB) that is the argmin of the measured
batch-path latency on three certified families (qwen3_8b, llama_3_1_8b,
gpt_oss_120b) over four corpus types (prose, code, chat transcripts and
a multilingual mix) at 64 K to 4 M characters on one 16-core NUMA node.
Representative readings at 1 M characters of English prose with 16
workers: 26.5 ms serial to 8.6 ms chunked on qwen3_8b (3.1x); 9.8 ms to
6.9 ms on llama_3_1_8b (1.4x), where the Python boundary -- each chunk's
ids handed over and concatenated -- is most of what remains. Every
chunked encode in that measurement (33,518 of them, up to 10 M
characters) returned the ids of the from-scratch reference, and the
shipped test `tests/test_cpe.py` repeats the identity check on every
certified family whose artifact it finds locally, over three corpus
types and three lengths, against the oracle package.

Guidance and limits are in `docs/serving.md` Section 3. Two of them
bear repeating: below 256 K characters a single encode is already as
fast, and a process started with `RAYON_NUM_THREADS=1` gets the chunks
one after another -- exact, not faster.

## Patch-only session append (`Session.append_patch`)

`Session.append(text)` returns a `SessionUpdate` that carries the whole
stream; a serving process usually holds that stream itself and only
needs the splice. `Session.append_patch(text)` returns a `SessionPatch`
-- `replace_from` and `replacement_ids`, nothing else -- from the same
append, with the same values `append` would report. `append` and
`SessionUpdate` are unchanged (`docs/contracts/facade.md` Section 7).

Honesty about what it saves today: on the native request path the
engine hands over the whole stream as one Python list on every append
(7.2 ms of the 7.6 ms an append over 220 K tokens costs), so
`append_patch` removes the update object and its copies and is not yet
proportional to the appended text. The Python surface is the one that
will not change when a patch-shaped native return lands (registered
below).

## Stateless calls: say so

`encode(text)` with `lookup` omitted asks the content index to digest
the input so a later request can find it. On a request that is never
extended that state construction is pure overhead -- 55-79 % of the
encode itself at 1 M characters -- and a serving path that knows a
request is single-shot should pass `lookup="off"`. The default is not
changing, because the facade cannot tell a single-shot request from the
first turn of a conversation; the serving layer can, and
`docs/serving.md` Section 1 lays out the four request shapes and the
call for each. The SGLang adapter's stateless mode already does this.

## SGLang adapter

`src/toktier/integrations/sglang.py` (new in this cycle; see
`docs/integration/sglang.md`) gains `AdapterConfig.cpe_min_chars` and
`cpe_k` (`TOKTIER_SGLANG_CPE_MIN_CHARS`, `TOKTIER_SGLANG_CPE_K`): with a
threshold set, a request that would be a stateless full encode --
every request in `off` mode, a keyless one in `contextvar` mode -- of
at least that many characters is served by `chunked_encode`, recorded
in the timing log as `how: "cpe"` with the chunk facts. Off by default;
keyed requests and `auto` mode are untouched; an explicit
`long_request_encoder` keeps precedence.

Three corrections from the release-candidate review. The wrapper now
establishes, before it accelerates anything, that the Hugging Face
object it was handed is the tokenizer toktier loaded: the supplied
object's serialized fast backend (tokens added after loading included)
and toktier's loader face are compared on the sections that decide the
core id stream -- model, normalizer, pre-tokenizer, added tokens,
truncation and padding state (`check_core_identity`). A family or
repository name alone cannot establish this. When the two differ, or one
side cannot be serialized, every call is delegated to the supplied
tokenizer for the wrapper's whole life and the reason is recorded
(`stats()["identity"]`; `TOKTIER_SGLANG_IDENTITY=skip` turns the check
off at the operator's risk). Attribute writes now follow attribute reads
(`tokenizer.chat_template = ...`, which SGLang's template manager
assigns, lands on the wrapped object where `apply_chat_template` reads
it). And the asynchronous shadow check judges against an independent
copy of the supplied object rather than a fresh load by name; when no
copy can be made it runs synchronously against the object itself.

## Registered for 0.2.11 (native)

- A Rust `ChunkEncoder`: the cut search and the concatenation below
  PyO3, so the per-chunk Python boundary stops being the floor.
- Batch workers forked and warmed at construction rather than on the
  first batch (about 20 ms per worker today); concurrent `encode_batch`
  callers taking disjoint idle workers instead of sharing a prefix of
  the pool; the 64 KiB-per-worker floor as a parameter.
- Per-chunk guard judgement inside `encode`, so an unchunked request
  pays reference speed only for the passage that tripped a guard.
- A patch-shaped native return for session appends, behind the
  `append_patch` surface shipped here.

Each of these touches a file in a certified identity's path set and is
therefore a release of its own, recertified against its own build.
